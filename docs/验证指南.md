# 验证指南：怎么证明「摄像头接入 + 模块联调」真的实现了

> 面向评审/答辩/交接。核心原则：**不听「我跑通了」，只认可复现的命令 + 输出证据。**
> 下面每条都给了「命令 / 看什么 / 通过判据 / 造不了假的点」。

## 一条命令自证

```bash
# 在本仓库任意位置、任意机器执行（Windows / 树莓派 / CI 都行）
python scripts/verify_catvision.py            # 自动识别仓库根
python scripts/verify_catvision.py /path/to/TNR   # 也可显式指定仓库根
```

脚本会跑 L1~L5 五层验证，逐项打印 `[PASS]/[FAIL]`，最后给总判定与退出码
（全过 `exit 0`；任一失败 `exit 1`，可直接接进 CI）。

- 没有摄像头的电脑（如开发机）：L1~L4 全绿，L5 打印 `[SKIP]`。
- 树莓派插着 CSI 摄像头：L1~L5 **全部**应为 `[PASS]`。

## 五层验证（从「不依赖硬件」到「真硬件」）

| 层 | 验证什么 | 命令 | 通过判据 | 这个判据造不了假的原因 |
|----|----------|------|----------|------------------------|
| **L1 单元** | 采集/抽帧/事件总线/决策逻辑 | `pytest tests/test_camera.py tests/test_pipeline.py -q` | 全绿（40 用例） | 用例里含「坏格式拒绝」「Ticker 限速」「FrameWriter 裁剪」等负向断言，不是只跑 happy path |
| **L2 源等价** | 合成源能跑通**全链路** | `python -m pipeline.runner --source synthetic:30 --mock-all` | 打印 `PIPELINE OK` 且 `detections≥1 actions≥1` | 脚本会解析 JSON 摘要核对数字，并 grep `FEED_DISPENSE`；只跑不产事件算失败 |
| **L3 真帧回放** | **真图片**进链路，不靠合成源 | `--source file:<图片目录>` | `source.frames_read=N` 且 `source.frames_failed=0` | 自动生成 20 张 640×480 真 JPEG 再跑；合成源在这里用不了，必须真的解码图片 |
| **L4 契约联调** | 三模块接口对齐 + 坏输入硬失败 | `pytest tests/contract -q` | 契约测试全绿；协议不满足 `exit=2`；坏路径 `exit≠0` | 故意塞一个不合协议的类，必须被 `[契约不满足]` 早拦截；坏路径必须报错，不能静默兜底 |
| **L5 真摄像头** | **真实 CSI 摄像头**出帧进链路 | `--source csi://0 --fps 2 --frames 10` | `PIPELINE OK` 且 `source.kind=csi`、`frames_failed=0` | 只有在 `/dev/video0` 存在且能 `import picamera2` 时才执行，否则 `[SKIP]`；插没插摄像头无法伪装 |

## 三级「真假判据」（反造假检查表）

1. **源是等价的，不是特例**：`csi:// / usb:// / rtsp:// / file: / synthetic:` 对下游都产同一种
   `FramePacket`（`modules/camera/source.py` 的 `parse_source` + `open_source` 工厂）。
   所以「合成源过了」不等于「摄像头过了」，**必须 L5 单独过**。
2. **只传路径不传图**：`FramePacket.image_path` 指向落盘文件，Pi 上在
   `/dev/shm/catvision/frames/cam0`（本机退化到临时目录），只保留最近 `--keep-frames`（默认 120）帧。
   验证「真的在抽帧」：看 `capture.effective_fps` / `measured_fps` 是否贴近 `--fps`（默认 3）。
3. **决策真触发 + 默认安全**：投粮需「matched + similarity≥0.80 + 画面只有一只猫 + 距上次投粮 >6h + 10s 防抖」；
   TNR 需 `neutered=false + confidence≥0.80`。默认 **dry-run**（`payload.dry_run=true`，不开电机）。
   验证「不投粮」：双猫同框必须 `actions=0`（`--mock-multi-cat-ratio 1.0`）。

## 在树莓派上跑（真摄像头，最终验收）

```bash
cd /home/lyx/catvision
LANG=C.UTF-8 PYTHONIOENCODING=utf-8 \
  /home/lyx/venvs/catvision/bin/python scripts/verify_catvision.py /home/lyx/catvision
```

单独看真摄像头这一条：

```bash
python -m pipeline.runner --source csi://0 --fps 2 --frames 10 --mock-all
# 期望：capture.source.kind = csi，frames_failed = 0，最后打印 PIPELINE OK
```

排障顺序：`vcgencmd get_throttled` 必须为 `0x0`（非 0 = 供电不足，先换 5V/3A）；
`ls /dev/video0` 有设备；`python -c "import picamera2"` 能导入（venv 需 `--system-site-packages`）。
