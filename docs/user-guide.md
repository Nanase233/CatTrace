# CatTrace 用户说明书

本文档面向评审教师和平台使用者，说明 CatTrace MVP 阶段的三项核心功能。

---

## 阅读指南

本文档使用功能等级标注，含义如下：

| 等级 | 含义 | 说明 |
|------|------|------|
| P0 | MVP 必须实现 | 没有该功能，平台无法运行 |
| P1 | 增强体验 | 有了它用户体验更完整，但非 MVP 必须 |
| P2 | 技术亮点 | 提供竞争力，可在 MVP 之后迭代 |
| P3 | 远期规划 | 长期愿景，当前阶段不做实现 |

当前三项核心功能均为 P0 等级。每项功能末尾标注了实际完成状态。

本文档仅覆盖三项核心功能。辅助功能（用户认证、日记、领养、举报、财务看板等）请参阅 [business-plan.md](./business-plan.md) 第 3.2 节。

---

## 功能一：实时直播与在线巡检

**等级**: P0
**状态**: MVP 模拟（非真实硬件控制）

### 功能定位

在小区、校园、公园的智能猫屋部署摄像头与环境传感器，让用户和志愿者可以远程实时查看猫咪状态，巡查猫屋运行情况。

该功能对应平台首页（`/`），是用户进入平台后的第一个交互界面。

### 使用步骤

1. 打开平台首页，页面自动加载实时直播区域。
2. 直播区域展示当前猫屋画面。当前 MVP 阶段为模拟画面（含猫咪动画），非真实视频流。
3. 页面底部环境数据栏显示当前猫屋的温度、湿度、今日投喂次数。当前数据为前端模拟值，每 5 秒刷新一次。
4. 页面显示当前在线观看人数（模拟值）。
5. 点击"投喂一份"按钮可在直播页面直接发起投喂（跳转至投喂功能）。
6. 点击"当前猫咪信息"按钮可查看当前画面中猫咪的档案摘要。

### 数据/记录说明

| 数据项 | 来源 | MVP 阶段状态 |
|--------|------|-------------|
| 直播画面 | 树莓派/香橙派摄像头推流 | 模拟动画，非真实视频 |
| 温度数据 | DHT22 传感器 | 前端随机生成，范围 20-35 度 |
| 湿度数据 | DHT22 传感器 | 前端随机生成，范围 40-80% |
| 今日投喂次数 | 后端 API `/api/stats` | 真实数据 |
| 在线观看人数 | 后端统计 | 模拟固定值 |

### 自学习子能力

| 能力 | 说明 | 状态 |
|------|------|------|
| 异常行为样本采集 | 检测到异常行为时自动截取视频帧存档，用于后续训练 | 待开发 |
| 低置信度样本人工标注 | 识别不确定时请求志愿者人工确认，积累标注数据 | 待开发 |

以上两项能力依赖硬件摄像头实际接入，当前 MVP 阶段暂未实现。

### 验收标准

1. 首页可正常加载，直播区域显示模拟画面与环境数据。
2. 环境数据（温度、湿度）按固定间隔刷新，数值在合理范围内波动。
3. 点击"投喂"按钮可正常跳转至投喂流程。
4. 页面在移动端浏览器中可正常显示与交互。

### 关于硬件接入的说明

规划方案为：树莓派 4B 或香橙派 Orange Pi Zero 3 作为边缘节点，接入 USB/CSI 摄像头与 DHT22 环境传感器，通过 MJPEG 推流或快照轮询将画面传输至平台。ESP32 仅用于独立的轻量传感器扩展节点，不参与直播推流链路。

## 功能二：远程投喂与投喂追溯

**等级**: P0
**状态**: 已完成

### 功能定位

用户通过平台对指定猫咪执行投喂操作，系统记录完整的投喂链路（谁、何时、喂了哪只猫），所有记录可追溯、可查询、可导出。

该功能贯穿首页直播区域和猫咪档案页（`/cats`），是平台最核心的用户交互。

### 使用步骤

1. 在首页直播区域点击"投喂一份"按钮，或在猫咪档案页点击对应猫咪卡片上的"投喂"按钮。
2. 系统弹出投喂对话框，要求填写昵称（游客模式）或自动使用已登录用户名。
3. 点击确认投喂。
4. 系统记录投喂日志，对应猫咪的投喂次数 +1，页面实时刷新统计数字。
5. 投喂记录可通过 `/api/feed-logs` 接口查询，支持按猫咪筛选。

### 数据/记录说明

每条投喂日志包含以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| timestamp | 投喂时间戳（ISO 8601） | 2026-10-19T14:32:05 |
| cat_id | 目标猫咪 ID | 1 |
| user_name | 投喂者昵称 | 小明 |
| is_logged_in | 是否已登录 | true / false |
| food_type | 投喂包类型 | standard |

**安全限制**：

| 用户类型 | 投喂限制 | 说明 |
|---------|---------|------|
| 游客（未登录） | 最多 1 次 | 防止未登录用户刷数据 |
| 登录用户 | 无限制 | 正常交互 |

投喂数据持久化存储于 `data.json` 的 `feed_logs` 字段中，上限 500 条（可通过环境变量 `PROJECTCAT_MAX_FEED_LOGS` 调整）。全量数据可通过 `/api/export` 一键导出。

### 自学习子能力

投喂操作完成后，系统自动触发自学习引擎（`self_learning.py`）更新分析：

| 能力 | 说明 | 状态 |
|------|------|------|
| 投喂规律学习 | 自动统计每只猫的日均投喂次数、高峰时段，输出行为画像 | 已完成 |
| 异常投喂提醒 | 单日投喂次数超过历史均值 2 倍时，生成异常预警记录 | 已完成 |
| 阈值自校准 | 根据累积的历史数据自动调整告警阈值，避免误报 | 已完成 |
| 用户偏好学习 | 记录每个用户关注的猫咪和投喂时段，生成用户画像 | 已完成 |

自学习结果可通过以下接口查询：

- 猫咪画像：`GET /api/learning/cat-profile/<id>`
- 用户画像：`GET /api/learning/user-profile/<user_id>`
- 异常预警：`GET /api/learning/anomalies`

### 验收标准

1. 游客模式投喂 1 次后，系统拒绝第 2 次投喂并提示登录。
2. 登录用户可连续投喂，每次操作后猫咪 `feed_count` 准确 +1。
3. 投喂记录可通过 `/api/feed-logs` 查询，字段完整且时间戳准确。
4. 投喂操作触发自学习引擎后，`/api/learning/cat-profile/<id>` 返回的 `peak_hours` 与 `avg_daily_feeds` 数值与实际投喂数据一致。
5. 短时间内大量投喂（超过均值 2 倍）后，`/api/learning/anomalies` 出现对应的异常记录。

## 功能三：AI 猫咪档案

**等级**: P0
**状态**: 已完成

### 功能定位

为每只建档的流浪猫创建完整的数字身份档案，包含基本信息、健康状态、绝育记录、位置信息和互动数据。档案页（`/cats`）是用户浏览猫咪、了解猫咪详情的主要入口。

### 使用步骤

1. 点击导航栏"猫咪档案"进入档案页（`/cats`）。
2. 页面展示所有建档猫咪的卡片列表，每张卡片显示猫咪头像、名字、昵称、位置、健康状态和绝育状态。
3. 使用顶部筛选栏可按条件过滤：全部 / 可领养 / 已绝育 / 需关注。
4. 使用搜索框可按名字、昵称、位置进行关键词搜索。
5. 点击猫咪卡片展开详情面板，查看完整档案信息和历史投喂数据。
6. 档案页内嵌 Chart.js 图表，展示猫咪的投喂趋势曲线。

### 数据/记录说明

每只猫的档案包含以下字段：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | number | 唯一标识 | 1 |
| name | string | 名字 | 咪咪 |
| nickname | string | 昵称 | 小区一霸 |
| gender | string | 性别 | female / male |
| age | string | 年龄 | 2 岁 |
| color | string | 毛色 | 橘白相间 |
| location | string | 位置 | A 区 - 教学楼后 |
| health | string | 健康状态 | 健康 / 需关注 |
| neutered | boolean | 是否绝育 | true / false |
| adoption_ready | boolean | 是否可领养 | true / false |
| feed_count | number | 累计投喂次数 | 156 |

当前系统内置 4 只示例猫咪（咪咪、小黑、雪球、大橘），用于演示完整功能流程。

**位置脱敏规则**：普通用户仅看到区域信息（如"A 区"），认证志愿者可看到精确位置（如"A 区 - 教学楼后"）。该规则由后端 `/api/location/<cat_id>` 接口根据用户权限动态返回。

### 自学习子能力

| 能力 | 说明 | 状态 |
|------|------|------|
| 健康评分 | 基于进食规律、情绪稳定性、活跃趋势自动计算 0-100 分 | 已完成 |
| 健康判断规则校准 | 根据用户反馈（如举报猫咪生病）持续优化健康评分参数 | 已完成 |
| 猫脸识别辅助建档 | 通过照片自动识别猫咪身份，减少人工建档工作量 | 规划中 |

健康评分公式：

```
健康分 = 基础分(70) + 进食规律分(0-15) + 情绪稳定分(0-10)
       + 活跃趋势分(0-5) - 异常扣分(0-30)
```

健康报告可通过 `GET /api/learning/health-report/<id>` 查询。

### 验收标准

1. 档案页正常加载，展示所有猫咪卡片，字段完整无缺失。
2. 筛选功能（全部/可领养/已绝育/需关注）正确过滤卡片列表。
3. 搜索功能可按名字、昵称、位置进行模糊匹配。
4. 点击猫咪卡片后，详情面板展示完整档案信息。
5. 投喂趋势图表（Chart.js）正确渲染，数据与实际投喂记录一致。
6. 健康评分接口 `/api/learning/health-report/<id>` 返回 0-100 范围内的数值，且评分逻辑与投喂数据关联。
