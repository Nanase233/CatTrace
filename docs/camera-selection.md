# 摄像头选型（摄像头与联调负责）

## 结论先说

**第 1~3 周就用现有的 IMX219 打通，不买新硬件。**
白天场景完全够用，先把链路跑通比换镜头重要得多。
唯一要立刻花钱的是**电源**（5V/3A，¥30 左右）——现在这块 Pi 正在欠压节流，会拖慢一切。

## 对照表

| 方案 | 夜视 | 分辨率 | 接口 | Pi4 负担 | 价格 | 什么时候用 |
|---|---|---|---|---|---|---|
| **IMX219**（现有的） | ❌ 带 IR-cut | 3280×2464 | CSI 排线 | 最低（ISP 硬件加速） | 已有 | **W1~W3 默认** |
| IMX219 NoIR | ✅ 需 850nm 红外灯 | 同上 | CSI | 最低 | ¥50~80 | W3+ 要演示夜间时 |
| IMX477（HQ） | ❌ | 4056×3040 | CSI | 中（片大，带宽高） | ¥300+ | 要拍远距离/低照度，但 Pi4 带不动高频 |
| USB UVC + 红外 | ✅ 多自带 | 1080p | USB | 中高（MJPEG 解码吃 CPU） | ¥80~150 | 要夜视又不想动排线 |
| RTSP 网络摄像头 | ✅ 常有 | 1080p+ | 网口/WiFi | 低（解码在相机侧） | ¥150~400 | **多点位部署的最终形态** |

## 为什么第一期选 IMX219

1. **硬件 ISP 加速**。CSI 走的是 Pi 的 ISP，缩放/编码不占 CPU；USB 摄像头靠 CPU 软解 MJPEG，
   1GB 的 Pi4 上这个差别很实在。
2. **已经接上了**，实测 1080p@47fps，不需要任何改动。
3. **`picamera2` 支持双流**：lores 640×480 喂 AI，main 1080p 出图存档。
   USB 方案要自己缩两次。

## 关键参数怎么定

| 参数 | 取值 | 理由 |
|---|---|---|
| AI 输入 | 640×480 lores 流 | 猫脸在画面里能占 100px 以上就够；再大是浪费 |
| 抽帧率 | **2~3 fps** | 猫吃饭/路过是秒级行为，3fps 完全够判断；跟着 30fps 跑 Pi4 必死 |
| 出图存档 | main 流 1080p，**只在需要时取** | 1GB 内存下常开双流容易 OOM |
| 编码 | JPEG q88 | 一帧 ~150~250KB，落 `/dev/shm` 无压力 |
| 位置 | 距猫进食点 1.0~1.5m，**略高于猫头顶** | 俯视容易丢耳尖，平视/略俯最好 |

> **耳尖为什么关键**：剪耳标记在耳廓边缘，俯视或侧脸时耳尖被挡住 → 耳标模块只能判 `visible=false`。
> 摄像头高度和角度直接决定剪耳模块的可用率，这是硬件和 AI 之间最容易被忽视的耦合。

## 夜视（W3+ 再决定）

现有 IMX219 **带 IR-cut 滤镜**，晚上拍不到红外，实测夜间画面几乎全黑。
要夜视有两条路：

1. **换 IMX219 NoIR 模组 + 850nm 红外补光灯**（¥50~80）。
   便宜、保持 CSI 的优势，缺点是要拆机、且 NoIR 白天色彩偏红（需要后期校色）。
2. **USB 红外摄像头**。不用拆排线，直接插。缺点是 CPU 解码开销大。

**建议 W3 再决定**，取决于演示是否必须包含夜间。如果只是白天演示，这两笔钱都不用花。

## 如果要买 RTSP 摄像头

选型硬要求：

- [ ] 支持 **RTSP** 或 HTTP 拉流（不要只支持厂商私有 App）
- [ ] 红外夜视（IR-cut 可切换）
- [ ] 主码流 H.264（**不要 H.265**，Pi4 软解 H.265 会很吃力）
- [ ] 能关掉厂商云、纯局域网使用
- [ ] 固定 IP 或 DHCP 保留

拉流自检：

```bash
python -m modules.camera --source "rtsp://user:pass@192.168.1.10:554/stream1" --fps 2 --frames 5 -v
```

代码里已经设了 `-rtsp_transport tcp`——UDP 丢包会让画面撕裂，这是 RTSP 最常见的坑。
